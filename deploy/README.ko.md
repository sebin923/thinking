# 현재 PC GPU 서버 준비

EC2 웹과 GPU PC를 분리해서 배포할 때는 [EC2·GPU 배포 안내](README_EC2_GPU.ko.md)를 먼저 확인합니다.

## 2026-11-19 로컬 검토 구성

이번 적용 대상은 `http://127.0.0.1:5173`의 로컬 웹입니다. 공통 초안은 정제한 1,459개로 새로 학습한 Curated1459 어댑터와 비교 평가에 사용한 `curated_over1000_20261119` 작성 지시를 함께 사용합니다. 초안 생성 한도도 평가와 같은 512개 새 토큰입니다. 피드백·추천·채점처럼 JSON이 필요한 요청은 같은 Qwen3.5-2B의 기본 가중치로 처리합니다.

`llm_training/outputs/local_selection.json`에 현재 로컬 구성을 기록했습니다. `local_web.py start --with-model`은 이 파일이 있으면 기본으로 읽으며, `--selection-file`로 명시할 수도 있습니다. 새 모델은 40문항 비교에서 평균 자연스러움과 사실 보존이 개선됐지만 중요한 사실 오류 5건이 남아 엄격한 교체 기준은 통과하지 못했습니다. 운영 선정 파일 `llm_training/model_selection.json`은 Ver3를 유지합니다. 로컬 초안에는 검토용 표시와 주체·수량·조건 확인 항목이 표시됩니다. 이 항목은 모든 사실을 검증한다는 뜻이 아닙니다.

로컬 저장소는 운영 회원 자료와 분리된 SQLite입니다. 시연 계정 정보는 `llm_training/outputs/final_release_20261119/local_web/로그인_정보.txt`에 있으며 Git에 포함되지 않습니다. 새 모델의 로그인·네 글 유형·피드백·추천·채점 연결 확인 기록과 이전 실행 복구 정보는 `llm_training/outputs/curated_1459_study_20261119/local_application/`에 있습니다. 브라우저에서도 보고서 초안 미리보기와 검토 안내를 확인했습니다. 이는 기능 연결 확인이며 품질 합격을 뜻하지 않습니다. 비교 평가 원본과 이전 2,000개 모델 설정은 그대로 보존했습니다.

서버를 종료한 뒤 다시 켤 때는 프로젝트 루트에서 실행합니다. `--node`에는 설치된 Node 실행 파일 경로를 지정합니다.

```powershell
.venv-review\Scripts\python.exe deploy/local_web.py start --with-model --selection-file llm_training/outputs/local_selection.json --node "<node.exe 절대 경로>"
```

이미 포트가 사용 중이면 현재 실행을 확인합니다. 실행 기록은 `local_web/processes.json`과 `llm_training/outputs/gpu_server/server.json`에 있습니다. Windows 가상환경의 Python 실행기는 별도 자식 프로세스를 만들 수 있어 기록된 실행기 PID와 실제 포트 소유 PID가 다를 수 있습니다.

### 개인 설정 반영

사용자 설정이 있는 공통 초안은 같은 Curated1459 모델로 생성한 뒤 `surface_v1` 표현 편집을 적용합니다. 격식체 종결을 다듬고, 짧은 문장은 명시된 과거 행동 연결을 나누며, 긴 문장은 조건·인용문을 제외한 완결된 문장을 연결합니다. 수치나 행동 주체를 새로 추론하지 않습니다. 문장 길이는 전체 글 분량과 별개이며 웹 초안의 기본 목표는 설정과 관계없이 350자입니다. 자료가 적으면 분량 미달 안내가 유지됩니다.

이는 사용자 취향에 따른 표현 편집이며 개인별 모델 학습은 아닙니다. 이미 명확한 문장은 자신감 설정에서도 그대로일 수 있고, 불확실한 사실을 단정형으로 바꾸지 않습니다. 사용자 설정이 없는 중립 요청의 평가 프롬프트와 학습 가중치는 보존합니다. 기존 40문항 점수는 이번 표현 편집의 성능 점수가 아닙니다.

피드백은 인접한 동일 문장을 먼저 확인해 강조 의도가 아닌 경우의 정리를 제안합니다. 힌트 설정은 수정문을 제공하지 않습니다. 일반 수정 제안에서는 일부 수치·단위·부정·계획·조건·주체 표현을 바꾸는 후보를 제외하며, 이 검사로 모든 의미 오류를 검증할 수는 없습니다. 사용자별 어댑터가 없는 현재 `내 문체를 학습한 AI`는 개인 모델이 없다는 안내를 반환합니다.

실제 설정 비교와 제한 사항은 `llm_training/outputs/curated_1459_study_20261119/local_application/personalization_improvement.json`에 기록합니다.

### 주체 보존과 AI 기능 점검

`source_actor_v1`은 원문에 본인 주어가 명시되고 출력의 행동이 유일하게 대응되는 경우에만 생략된 나는·저는을 복원합니다. 같은 행동을 여러 사람이 했거나 대응이 불명확하면 추정하지 않고 원문 확인 안내를 남깁니다. 문체 편집은 이 주어를 유지합니다. 이 보완은 재학습이 아니라 서비스의 출력 처리 변경입니다.

피드백은 명확한 반복과 일부 의존 명사 띄어쓰기를 우선 확인하며, 본인 주어를 삭제하는 수정안도 제외합니다. 일반 AI 문장 판단과 채점 근거의 정확성에는 여전히 검토가 필요합니다. 자기소개서 문항형 연습은 학습자가 자신의 경험을 고르는 과제이므로, 참고 사실 목록에 없다는 이유만으로 경험을 지어냈다고 평가하지 않도록 채점 기준을 분리했습니다.

피드백·채점·추천의 구조화 요청은 기본 가중치를 사용하고, JSON 구조·필수 키·값의 범위를 검증합니다. 형식 오류나 토큰 중단에는 한 번만 간결한 재생성을 요청하며, 재실패하면 오류를 반환합니다. 점수나 필수 값을 임의로 채우지 않습니다. 자기소개서 추천 문항과 이유는 출력 길이를 줄여 토큰 한도에 맞춥니다.

실제 로그인 API 경로의 기능별 요청·응답, 정상 글과 사실을 바꾼 글 및 무관한 글의 대조 채점, 수정 전 오류와 재검증은 `llm_training/outputs/curated_1459_study_20261119/local_application/service_function_audit.json`에 보존합니다. 점검용 퀴즈 통과 상태는 분리된 로컬 시연 계정의 임시 단원에만 설정하고 검사 후 제거합니다.

## 기존 AWS 연결 계획

현재 구성은 AWS EC2의 웹·백엔드가 Tailscale을 통해 이 Windows PC의 Qwen API를 호출하는 방식입니다. **현재 배포는 보류 상태입니다.**

개인화 시연 데이터는 공통 학습에 합치지 않습니다. 공통 모델만으로 초안, 저장한 문체 설정, 피드백, 연습 주제 추천을 실행할 수 있습니다. 계정별 추가 학습은 이후 별도 실험입니다.

## 배포 없이 확인

프로젝트 루트에서 실행합니다. 모델 가중치를 불러오거나 서버를 시작하지 않습니다.

```powershell
llm_training\.venv\Scripts\python.exe deploy/gpu_server.py
```

사용할 결과가 정해지면 완료 여부도 확인합니다. 경로는 직접 지정하며 최신 결과를 자동으로 선택하지 않습니다.

```powershell
llm_training\.venv\Scripts\python.exe deploy/gpu_server.py --adapter llm_training/outputs/<선택한_완료_실행>/adapter
```

학습 전체의 최종 `metrics.json`, 학습 완료 기록, 최종 평가, 어댑터 파일을 확인합니다. 학습 완료는 출력 품질 승인을 뜻하지 않습니다.

## 나중에 배포를 재개할 때

1. 사용할 공통 어댑터를 선택하고 실제 서비스 입력으로 출력 품질을 확인합니다.
2. `thinking_llm_token` 파일과 EC2의 `THINKING_LLM_TOKEN`이 같은지 비밀값을 출력하지 않고 확인합니다. 토큰·환경변수·가중치는 Git에 올리지 않습니다.
3. 같은 명령에 `--start`를 추가하면 기존 `llm_training/.venv`로 로컬 API를 시작합니다. 기본 바인딩은 `127.0.0.1:8001`이며 Tailscale이나 AWS 설정은 변경하지 않습니다. 모델은 첫 생성 요청 시 로드됩니다.
4. 로컬 생성 확인 후 Tailscale Serve의 기존 설정을 확인하고 `tailscale serve --bg --tcp=8001 tcp://127.0.0.1:8001`로 tailnet 안에서 연결합니다. `tailscale funnel`은 사용하지 않습니다.
5. EC2에서 상태·인증·생성을 확인한 뒤 웹·백엔드를 반영합니다. 현재 EC2 저장소에 수정 사항이 있으므로 별도 릴리스 폴더와 복구 경로를 준비해야 합니다.

이 PC가 켜져 있고 절전 없이 Tailscale과 GPU API가 실행 중이어야 AWS의 AI 기능이 작동합니다. 같은 GPU에서 학습과 추론을 동시에 실행하기 전에는 메모리 여유를 확인하세요.

기존 CUDA 환경은 torch `2.14.1+cu126`, transformers `5.21.0`, peft `0.21.2`, accelerate `1.15.0`입니다. API 준비 과정에서 FastAPI `0.128.0`과 Uvicorn `0.40.0`을 추가했습니다. 로컬 모델 추론과 웹 연결은 위의 검토 구성에서 확인했습니다.

참고: [Tailscale Serve 명령](https://tailscale.com/docs/reference/tailscale-cli/serve).
